# 상세페이지 만들기

한 번에 끝까지: **받기 → 참고 뜯기 → 구조표 → HTML → 검수 → 내보내기**. 중간에 묻지 말고 빠진 값은 [missing-info](references/missing-info.md) 규칙대로 처리한다.

## 작업 폴더 (없으면 만든다)

```
<상품폴더>/
  product-info.md      상품 사실(이름·구성·사양·가격·후기·수치·표시 사항). 모르는 건 비워 둔다
  assets/              사용자 에셋(제품 사진·로고·성분 이미지). 이 폴더가 우선
  reference/           참고 페이지 수집물 (scripts/fetch_reference.py 결과)
  out/v01/             detail-page.html, assets/, structure.md, open-items.md, export/
```
폴더 위치가 안 주어지면 저장소 안의 `detail-pages/<상품 슬러그>/` (새 상품은 `detail-pages/_template/`을 복사해 시작).

## 순서

1. **받기.** 필수는 **상품 설명과 사진**(`product-info.md`, `assets/`)뿐이다. 참고 URL·캡처는 선택. 없는 건 묻지 않고 진행하되 `open-items.md`에 적는다.
2. **참고 수집.** 참고가 안 주어졌으면 직접 찾는다: 같은 카테고리에서 잘 팔리는 상세페이지 후보 3개를 `web_search`/네이버 쇼핑 상위 상품에서 골라 가장 구조가 좋은 1개를 쓴다(고른 이유 한 줄을 `structure.md`에 적는다). 참고의 이미지는 쓰지 않는다. URL이 주어졌거나 정했으면 `python3 scripts/fetch_reference.py <url> <상품폴더>/reference` (ego-browser). 긴 이미지는 `slices/`에 2000px 조각으로 나온다. **조각을 전부 눈으로 읽고**(y오프셋 = 조각번호×2000) 위에서부터 섹션을 나누어 한 줄씩 적는다: 무엇을 보여 주나 → 역할(멈추게·문제·해결·증거·구성·사용법·가격·안심·행동) → 손님의 속 질문. 참고가 없으면 [기본 순서](references/sections.md).
3. **구조와 훅.** [persuasion](references/persuasion.md): 경쟁 페이지 3~5개에서 **공통으로 나오는 섹션 순서**를 뽑아 그대로 뼈대로 쓰고, 첫 화면 훅 후보 3개를 만들어 가장 구체적인 하나를 고른다. 리뷰에서 반복되는 고객의 말은 훅과 공감 섹션의 재료로 쓴다(`research.md`). 근거표는 점검용으로만 짧게.
4. **짝짓기.** 섹션마다 내 상품의 사실을 고른다. 맞는 사실이 없으면 그 섹션을 뺀다. 참고 길이의 70% 이상, 섹션 12개 이상을 목표(참고가 없으면 12개 안팎).
5. **에셋 정하기.**
   - 사용자 에셋은 그대로 쓴다. **내장 이미지 생성 툴이 있으면(ChatGPT·Codex) 섹션에 필요한데 사진이 없는 연출컷만 [image-generation](references/image-generation.md) 규칙으로 만들어 쓴다.** 필요한 만큼만, 있는 사진으로 되는 자리는 만들지 않는다. 툴이 없으면 만들지 않는다.
   - 참고 페이지의 에셋(로고·제품 컷·아이콘·일러스트)은 **같은 제품의 공식 이미지이고 사용자가 허락했을 때만** 쓴다(허락이 없으면 한 번만 묻고, 그래도 모르면 쓰지 않는다). Pillow로 `out/vNN/assets/`에 잘라 저장한다. 글자가 박힌 조각은 여백 포함해 자르고, 우리 카피는 HTML 텍스트로 따로 쓴다.
   - 참고 페이지의 문장·다른 브랜드 이름은 가져오지 않는다.
6. **카피.** [copywriting](references/copywriting.md): **창작하지 말고 레퍼런스를 따라 쓴다.** 상위 판매 페이지의 제목·본문·수치 문구를 섹션별로 그대로 옮겨 적고(research.md), 문장 뼈대·어미·숫자 위치·섹션 순서를 유지한 채 상품명·성분·수치만 우리 것으로 치환한다. 상표·로고·원본 이미지·남의 시험 수치만 쓰지 않는다. 직접 쓰는 건 따라 쓸 수 없는 칸뿐(시적·감성 문장 금지). 건강기능식품·화장품은 표시 가능한 범위만, 효능 단정·최고·1위·유일 금지.
7. **HTML.** `out/vNN/detail-page.html`, `templates/base.css`를 복사해 색 변수만 상품 브랜드색으로 바꾼다. 480px 중앙, 외부 주소·외부 글꼴·스크립트 없음, 그라데이션 금지(브랜드색 2색+흰색). 구조는 `.page > section` (직계 자식이 섹션) — 내보내기 컷이 이 구조에 의존한다. 글꼴·행간은 [typography](references/typography.md). 컴포넌트: 번호 배지, 비교표, 체크리스트, 아이콘 카드, 성분 칩, 큰 숫자, 마지막 요약, 하단 고정 구매 바(`position:fixed`).
8. **검수.** ① `<img>` 경로가 전부 실제 파일인지 ls로 확인 ② 화면에 `[확인 필요]`·빈 상자·자리표시 없음 ③ 금지 항목 점검 ④ 결과를 브라우저(ego-browser가 있으면 그것, 없으면 Playwright)로 열어 480px 캡처를 구간별로 직접 본다(글자 겹침·잘림·이미지 깨짐). 고친 뒤 보고.
9. **내보내기.** (필요: `pip install playwright pillow` + `playwright install chromium`. ego-browser가 있으면 그것을 쓴다.) `python3 scripts/export.py out/vNN/detail-page.html out/vNN/export --platforms smartstore,coupang,html` ([platforms](references/platforms.md)). 요청한 플랫폼만. 확인하지 못한 규격은 '미확인'으로 보고.
10. **보고.** 길이·섹션 수·내보낸 파일 경로·`open-items.md` 요약(채우면 좋아지는 것)·미확인. 짧게.

## 수정

- 이전 결과를 덮어쓰지 않는다: `out/v01` → `out/v02`로 복사해서 고치고, `out/CHANGELOG.md`에 한 줄(무엇을 바꿨는지)을 추가한다.
- 수정 요청은 섹션 단위로 한다: 해당 `<section>`만 고치고 나머지는 그대로 둔다. 값이 새로 생기면(가격·후기·이미지) 그 섹션만 추가한다.
- 고친 뒤 7·8번(검수·내보내기)을 다시 돈다.

## 넣지 않는 것

- 받은 정보에 없는 후기·별점·판매량·만족도·인증·수상·숫자
- 지어낸 마감·남은 수량·"오늘만" (실제 날짜가 주어졌을 때만 그대로)
- 참고 페이지의 문장·브랜드 이름, 허락 없는 참고 사진
- 완치·치료·100%·최고·1위·유일 같은 과장·단정 표현
- 화면 안의 `[확인 필요]`, 회색 빈 상자, "준비 중"
